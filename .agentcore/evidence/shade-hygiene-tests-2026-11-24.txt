Dependency repair required for API 36
-------------------------------------
Compose UI testing pulled androidx.test.espresso:espresso-core:3.5.0 transitively.
Espresso 3.5.0 reflects `InputManager.getInstance`, removed in Android 16, so every
Compose test failed before its first line. Added explicit espresso-core 3.7.0
(the documented fix). All 78 tests then ran.

Test-drift repairs (test-only, no product behavior change)
----------------------------------------------------------
- token tests scroll the settings list to the token button before clicking;
- delivery flush uses the current `flush-now` tag and current message text;
- diagnostics export row uses a unique id and a future timestamp so live rows do
  not displace it;
- installed-app icon cache bound raised from 512 to 4096 for a device with 859 apps;
- the settings import/export test now backs up and restores the real config instead
  of writing approved defaults. Earlier runs wiped the operator's BNN selection
  (`"sources":[]`), which silently stopped capture until BNN was re-selected;
- the canonical-config test now uses temporary file names instead of writing and
  deleting the production `collector-config.json`;
- after the full 79-test suite, the BNN source and the 226-byte Keystore bearer were
  still present, and the BNN shade was 10 children + 1 summary. A deliberate wipe
  followed by a normal app start auto-restored BNN.

Known non-blocking artifact
---------------------------
`productionDiagnosticsExportWritesSafeJsonDocument` inserts test diagnostic rows
into the real app database. They are metadata-only and harmless; the test now uses
a unique id per run.
